What is Northwind? #

Northwind is a complete payments platform wrapped in a single REST API. You create charges to take money, customers to remember people, and payouts to move money back out. Everything is a resource with an id, a created timestamp and a predictable JSON shape — learn one endpoint and you have learned them all.

It is built for three kinds of builders: storefronts that need a checkout in an afternoon, marketplaces that split payments between sellers, and subscription products that bill on a schedule. The same key works in test mode and live mode; only the key changes.

Core concepts #

Four objects cover almost every payment flow you will build.

ObjectWhat it isExample id
ChargeA single payment from a customer — card, wallet or bank.ch_9f2…
CustomerA person or business you bill more than once.cus_41a…
PaymentMethodA saved card or bank account attached to a customer.pm_7c3…
PayoutMoney moving from your Northwind balance to a bank.po_58e…
Note

Every object in the API is returned in the same envelope: object, id, created and livemode. If a field is missing, it is null — never absent.

Base URL & environments #

All requests go to https://api.northwind.dev. Test mode and live mode share the same URL — the key you send decides which world you are in. Test keys start with nw_test_, live keys with nw_live_.

curl https://api.northwind.dev/v1/charges \
  -u nw_test_51H7example: \
  -d amount=2500 \
  -d currency=usd
const northwind = require('northwind')('nw_test_51H7example');

const charge = await northwind.charges.create({
  amount: 2500,
  currency: 'usd',
});

console.log(charge.id); // ch_9f2kL4mQ8
import northwind

northwind.api_key = "nw_test_51H7example"

charge = northwind.Charge.create(
    amount=2500,
    currency="usd",
)

print(charge.id)  # ch_9f2kL4mQ8

SDKs & libraries #

Official libraries exist for Node.js, Python, Ruby, PHP, Go and Java. They all share the same method names, so switching languages later costs you an afternoon, not a rewrite. Community libraries for Elixir, Rust and .NET are listed in the GitHub organisation.

New here? Skip the tour and go straight to Quickstart — you will make your first real (test) charge in under five minutes.

Chapter 02 · Getting started

Your first charge in five minutes.

This guide takes you from zero to a successful test payment. No account approval, no card details, no waiting — test mode is free and instant.

5 min read Updated Nov 18, 2026 API v3.2

Four steps, one payment #

  1. Get a test API key

    Create a free Northwind account, open Developers → API keys and copy the key that starts with nw_test_. Test keys can never move real money.

  2. Install the library

    Pick your language below and install the official package. The SDK handles authentication, retries and error parsing for you.

  3. Create your first charge

    Send amount and currency to POST /v1/charges. Amounts are always in the smallest currency unit — cents for USD, so 2500 means $25.00.

  4. Confirm it worked

    A 201 response with status: "succeeded" means the money moved (in test mode). Check the Dashboard to see the charge listed.

Install the SDK #

# No install needed — cURL is built into macOS and Linux.
curl https://api.northwind.dev/v1/charges \
  -u nw_test_51H7example:
npm install northwind
# or
yarn add northwind
pip install northwind
# or
poetry add northwind

Create your first charge #

The test card 4242 4242 4242 4242 always succeeds. Any future expiry date and any three-digit CVC work in test mode.

curl https://api.northwind.dev/v1/charges \
  -u nw_test_51H7example: \
  -d amount=2500 \
  -d currency=usd \
  -d source=tok_visa \
  -d description="Order #4821 — Leather tote"
const northwind = require('northwind')('nw_test_51H7example');

const charge = await northwind.charges.create({
  amount: 2500,
  currency: 'usd',
  source: 'tok_visa',
  description: 'Order #4821 — Leather tote',
});

console.log(charge.status); // "succeeded"
import northwind

northwind.api_key = "nw_test_51H7example"

charge = northwind.Charge.create(
    amount=2500,
    currency="usd",
    source="tok_visa",
    description="Order #4821 — Leather tote",
)

print(charge.status)  # "succeeded"

Chapter 03 · Guides

Keys, secrets and who can do what.

Northwind authenticates every request with a secret API key sent as a Bearer token. No OAuth dance, no sessions — just a key, kept secret, sent on every call.

8 min readUpdated Nov 12, 2026API v3.2

Your API keys #

Every account has two kinds of keys. Publishable keys (nw_pk_…) are safe to ship in a browser or mobile app — they can only create tokens, never move money. Secret keys (nw_sk_…, or the legacy nw_test_ / nw_live_ prefix) can do everything, and must only ever live on your server.

curl https://api.northwind.dev/v1/charges \
  -H "Authorization: Bearer nw_test_51H7example" \
  -H "Content-Type: application/json"
const northwind = require('northwind');

// The SDK reads the key from the environment —
// never hard-code it in your source.
const nw = northwind(process.env.NORTHWIND_SECRET_KEY);
import os
import northwind

# The SDK reads the key from the environment —
# never hard-code it in your source.
northwind.api_key = os.environ["NORTHWIND_SECRET_KEY"]
Never expose a secret key

Secret keys in client-side code, public repositories or screenshots are compromised the moment they are published. If a key leaks, roll it immediately from the Dashboard — old keys stop working within seconds.

Test mode vs live mode #

Test keys (nw_test_) talk to a sandbox full of fake data; live keys (nw_live_) move real money. The two modes are completely separate — test charges never appear in live reports, and test customers cannot be charged live. Switch modes by switching keys, nothing else changes.

Test modeLive mode
Key prefixnw_test_nw_live_
Real moneyNeverYes — real charges
Test cards4242… always succeedsReal cards only
WebhooksDelivered to test endpointsDelivered to live endpoints

Restricted keys #

For services that only need part of the API — a reporting job that lists charges, a support tool that reads customers — create a restricted key limited to specific resources and read-only access. If that service is ever compromised, the blast radius is exactly the permissions you granted, nothing more.

Rotating keys #

Rotate keys every 90 days, or immediately after any suspected leak. Northwind supports a grace period: create the new key, deploy it, then revoke the old one — requests made with either key succeed during the overlap, so rotation never causes downtime.

  1. Create a replacement key in Developers → API keys.
  2. Deploy the new key to every service that uses the old one.
  3. Revoke the old key. Revocation is immediate and permanent.

Chapter 04 · Guides

Requests that behave the same, every time.

One base URL, JSON everywhere, predictable status codes. This chapter covers the conventions shared by every endpoint — idempotency, pagination, filtering and versioning.

9 min readUpdated Nov 10, 2026API v3.2

Request basics #

Send JSON bodies with Content-Type: application/json and authenticate with a Bearer token. Successful creates return 201, successful reads return 200, and deletes return 200 with the deleted object marked deleted: true.

curl https://api.northwind.dev/v1/charges/ch_9f2kL4mQ8 \
  -H "Authorization: Bearer nw_test_51H7example"
const charge = await northwind.charges.retrieve('ch_9f2kL4mQ8');
console.log(charge.amount); // 2500
charge = northwind.Charge.retrieve("ch_9f2kL4mQ8")
print(charge.amount)  # 2500

Idempotency — never charge twice #

Networks fail mid-request. To make retries safe, send a unique Idempotency-Key header with every POST. If the same key is sent twice within 24 hours, the second request returns the original response instead of creating a second charge. Generate keys with a UUID — never reuse a key for a different payment.

curl https://api.northwind.dev/v1/charges \
  -u nw_test_51H7example: \
  -H "Idempotency-Key: 7b4e2a91-3c1d-4f8a-9e2b-1a5c6d7e8f90" \
  -d amount=2500 \
  -d currency=usd
const { randomUUID } = require('crypto');

const charge = await northwind.charges.create(
  { amount: 2500, currency: 'usd' },
  { idempotencyKey: randomUUID() },
);
import uuid
import northwind

charge = northwind.Charge.create(
    amount=2500,
    currency="usd",
    idempotency_key=str(uuid.uuid4()),
)

Pagination #

List endpoints return pages of up to 100 items, newest first. Every list response includes has_more and the data array; pass the last item's id as starting_after to fetch the next page. Cursor pagination stays stable even while new charges arrive.

curl "https://api.northwind.dev/v1/charges?limit=10&starting_after=ch_9f2kL4mQ8" \
  -u nw_test_51H7example:
let charges = [];
let page = await northwind.charges.list({ limit: 10 });

while (page.has_more) {
  charges.push(...page.data);
  page = await northwind.charges.list({
    limit: 10,
    starting_after: page.data[page.data.length - 1].id,
  });
}
charges = []
page = northwind.Charge.list(limit=10)

while page.has_more:
    charges.extend(page.data)
    page = northwind.Charge.list(
        limit=10,
        starting_after=page.data[-1].id,
    )

Filtering & sorting #

Most list endpoints accept created (a Unix timestamp or a range like created[gte]=1794000000), customer and status. Results are always sorted by creation date, newest first.

API versioning #

Northwind versions the API by date in the URL (/v1/… today, with a Northwind-Version header for pinning). Upgrades are opt-in: your integration keeps the version it was built against until you change the header. Breaking changes are announced 90 days in advance and listed in the changelog.

Note

Pin your version in production. The Dashboard always shows the version each key is pinned to, so a teammate can see at a glance what your integration expects.

Chapter 05 · Guides

When things go wrong, know exactly why.

Every failure returns the same error object: a machine-readable code, a human-readable message, and a type that tells you whether to retry, fix the request, or ask the customer for help.

7 min readUpdated Nov 8, 2026API v3.2

The error object #

{
  "error": {
    "type": "card_error",
    "code": "card_declined",
    "message": "Your card was declined.",
    "param": "source",
    "decline_code": "insufficient_funds"
  }
}

Error codes #

Hover any row for the full story behind the code.

400 · invalid_request
The request body failed validation. The param field names the offending parameter — check its type and format, then resend.401 · authentication_error
No valid key was presented. Verify the key prefix (nw_test_ / nw_live_) and that it has not been revoked in the Dashboard.402 · card_declined
The card issuer declined the charge. decline_code explains why (e.g. insufficient_funds, expired_card). Show the customer a friendly message and offer another payment method.429 · rate_limit
You hit your plan's per-minute limit. Wait for the Retry-After header (seconds), then retry with exponential backoff. See the Rate limits chapter.500 · api_error
An unexpected error on Northwind's side. Retry once with the same idempotency key; if it persists, contact support with the request_id from the response headers.
StatusCodeWhat happenedRetry?
400invalid_requestA parameter is missing or malformed.No — fix the request
401authentication_errorThe API key is missing, wrong or revoked.No — check the key
402card_declinedThe bank refused the payment.No — ask the customer
429rate_limitToo many requests in a short window.Yes — back off
500api_errorSomething broke on our side.Yes — retry once

WarningNever retry a 402 automatically. Each attempt can count as a new authorisation on the customer's statement — retrying a declined card is how support tickets are born.

Retrying the right way #

Retry only 429 and 5xx errors, with exponential backoff: wait 1s, then 2s, then 4s, and stop after three attempts. Always reuse the same Idempotency-Key so a retry can never create a duplicate charge — the key is what makes a retry safe instead of dangerous.

async function chargeWithRetry(params, attempts = 3) {
  for (let i = 0; i < attempts; i++) {
    try {
      return await northwind.charges.create(params, {
        idempotencyKey: 'order-4821',
      });
    } catch (err) {
      const retryable = err.status === 429 || err.status >= 500;
      if (!retryable || i === attempts - 1) throw err;
      await sleep(1000 * 2 ** i); // 1s, 2s, 4s
    }
  }
}
import time
import northwind

def charge_with_retry(params, attempts=3):
    for i in range(attempts):
        try:
            return northwind.Charge.create(
                **params,
                idempotency_key="order-4821",
            )
        except northwind.error.RateLimitError:
            if i == attempts - 1:
                raise
            time.sleep(2 ** i)  # 1s, 2s, 4s

Chapter 06 · Guides

Let Northwind call you back.

Webhooks tell your server when something happens — a charge succeeds, a subscription renews, a payout lands. Instead of polling, you listen.

8 min readUpdated Nov 5, 2026API v3.2

Setting up an endpoint #

Register a public HTTPS URL in Developers → Webhooks and choose the events you care about. Northwind sends a POST with a JSON event object every time one fires. Your endpoint must answer 200 within 10 seconds — anything else counts as a failed delivery and gets retried.

app.post('/webhooks/northwind', (req, res) => {
  const event = req.body;

  if (event.type === 'charge.succeeded') {
    fulfillOrder(event.data.object);
  }

  res.sendStatus(200); // acknowledge fast, work after
});
from flask import Flask, request

app = Flask(__name__)

@app.post("/webhooks/northwind")
def webhook():
    event = request.json

    if event["type"] == "charge.succeeded":
        fulfill_order(event["data"]["object"])

    return "", 200  # acknowledge fast, work after

Verifying signatures #

Anyone can POST to your endpoint, so every webhook carries an Northwind-Signature header — an HMAC-SHA256 of the raw body, signed with your endpoint's secret. Verify it before trusting the payload; the SDK does this in one call.

const event = northwind.webhooks.constructEvent(
  req.rawBody,
  req.headers['northwind-signature'],
  process.env.NORTHWIND_WEBHOOK_SECRET,
);
// Throws if the signature does not match.
event = northwind.Webhook.construct_event(
    request.data,
    request.headers["Northwind-Signature"],
    os.environ["NORTHWIND_WEBHOOK_SECRET"],
)
# Raises if the signature does not match.
Never skip verification

An unverified webhook endpoint is an open door: anyone who guesses the URL can fake a charge.succeeded event and trick your system into shipping orders that were never paid for.

Event types #

EventFires when
charge.succeededA payment completes successfully.
charge.failedA payment is declined or fails.
charge.refundedA charge is refunded, fully or partially.
customer.createdA new customer object is created.
payout.paidMoney leaves your balance for your bank.
subscription.renewedA subscription bills for a new period.

Delivery & retries #

If your endpoint does not answer 200, Northwind retries with exponential backoff for up to 3 days — roughly a dozen attempts. Events can arrive more than once and occasionally out of order, so store each event's id and ignore duplicates, and always read the object's current state from the API rather than trusting the order of arrival.

How fast can you go?

Northwind limits requests per minute, per plan, so one noisy integration can never slow down everyone else. Limits are generous, headers tell you exactly where you stand, and the dashboard shows your usage in real time.

Reading the headers #

Every response carries your current budget. Check these headers before you decide whether to fire the next request.

HeaderMeaning
X-RateLimit-LimitYour plan's limit for this minute.
X-RateLimit-RemainingRequests left in the current window.
X-RateLimit-ResetUnix time when the window resets.
Retry-AfterSeconds to wait — only sent with a 429.

Handling a 429 #

When you hit the limit you get a 429 with a Retry-After header. Wait that many seconds, then continue — do not hammer the API in a tight loop, or the window keeps resetting. If you regularly hit your limit during normal traffic, that is the API telling you it is time to upgrade or to batch your work: list endpoints accept up to 100 items per page, and webhooks replace most polling entirely.

Tip

Test-mode limits are ten times lower than live limits on the same plan, on purpose — it forces you to write polite code before real money is involved.
